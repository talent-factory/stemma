\chapter{Phase 1: Lokaler Kern}

\section{Ziel}

Ein lokales Repository mit einem Nutzer. Es lässt sich anlegen, Dateien werden gespeichert, Commits erzeugt und der Status angezeigt.

\section{Umfang}

\startitemize
\item Objektspeicher mit Blobs, Trees und Commits, adressiert über BLAKE3 mit Präfix nach ADR-001.
\item Referenzen für den Branch \type{main} und HEAD.
\item Arbeitskopie als Commit mit Snapshot bei jedem Befehl und Change-IDs (ADR-010).
\item Befehle \type{init}, \type{add}, \type{commit} und \type{status}.
\item Akteur-Felder in jedem Commit und im Operation Log nach ADR-002.
\stopitemize

\section{Aufbau eines Repositories}

Ein Repository ist ein Verzeichnis, das einen Ordner \type{.stemma} enthält. Die Schicht \type{Repository} in \type{stemma-core} bündelt Objektspeicher und Referenzen, damit jede Operation die Speicher desselben Repositories verwendet (ADR-009).

\starttyping
.stemma/
    format        stemma-repository 1
    HEAD          branch main
    objects/      lose Objekte
    refs/heads/   Branches
    tmp/          temporäre Dateien des Objektspeichers und der Referenzen
\stoptyping

Die Datei \type{format} trägt eine Versionsnummer. Beim Öffnen lehnt der Kern eine fehlende, eine nicht kanonische und jede andere Version ab. Ein älteres Programm weist damit ein neueres Repository zurück, statt es zu beschädigen.

Die Funktion \type{Repository::init} baut den Ordner unter einem temporären Namen neben \type{.stemma} auf und benennt ihn am Ende um. Ein Fehler entfernt den temporären Ordner wieder und hinterlässt so kein halbes Repository; gelingt auch das Entfernen nicht, nennt die Fehlermeldung den Ordner. Existiert \type{.stemma} bereits, bricht \type{init} ab und ändert nichts. Alle neuen Dateien und Ordner werden auf den Datenträger geschrieben. Der Standard-Branch ist \type{main}, der Kern nimmt ihn als Option entgegen. Der Befehl \type{stemma init} bietet ihn als \type{--initial-branch} an. HEAD zeigt auf den Branch, der Branch selbst entsteht erst mit dem ersten Commit. Wie jede Operation ruft \type{init} zuerst \type{authorize} mit dem Akteur auf.

Den Akteur liest die Kommandozeile aus dem Schalter \type{--actor} oder der Umgebungsvariablen \type{STEMMA_ACTOR}. Der Text hat die Form der Akteur-Zeile eines Commits, also \type{human daniel} oder \type{agent claude model=opus-5-5 session=s1 sponsor=daniel}. Der Schalter geht der Variablen vor. Ein leerer Wert gilt als Fehler und fällt nicht auf die Variable zurück. Ohne Akteur bricht der Befehl ab und legt nichts an. Einen Standardwert aus dem Benutzernamen gibt es bewusst nicht, damit ein Agent nie stillschweigend als Mensch auftritt.

\section{Offene Fragen}

\startitemize
\item Format des Index: eigenes Binärformat oder lesbares Textformat für Debugging?
\item Ausführbare Dateien und Dateirechte: Welche Metadaten werden gespeichert?
\item Symbolische Links: Speichern oder ablehnen?
\item Syntax der Ausschlussdatei und das Entfernen von Geheimnissen aus Verlauf und Log (ADR-010).
\stopitemize
